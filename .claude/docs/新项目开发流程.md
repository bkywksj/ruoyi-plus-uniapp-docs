# 新项目开发流程：从一句话想法到上线

```
一句话想法
  │
  ▼
[1] /kickoff 阶段一：联网调研 + 头脑风暴 → docs/需求文档.md（REQ-00x + 里程碑）   🚦 人工门①（你确认「做什么」）
  │                                          在框架模板里只落盘、不提交
  ▼
[2] /kickoff 阶段二：AI 工作站 ai-ui-studio 出原型 → docs/prototypes/  🚦 人工门②（你确认「长什么样」）
  │
  ▼
[3] project-init：问你写到哪个目录 → 复制框架 → 改 site.config.ts → 写 .claude/PROJECT.md → 本地 git 首次提交
  │                                          🔴 建远程仓库与推送走 Sigil（只建私有仓）
  │   （在已孵化的项目里跑 /kickoff：跳过这一步，直接起飞）
  ▼
[4] 起飞：/loop /dev-loop（单会话）或 /dev-orchestrate（智码多会话）
  │     第 0 轮：writing-plans 按需求 + 原型拆 docs/tasks/active/ 台账（T1、T2…全局唯一编号）
  │     之后每轮：一个 T 任务 → /dev、/collection、html-to-code 等 → 验证门 → 两段 review → 规范提交
  │     可逆的小决定记 docs/BLOCKERS.md 继续做；需决策的停下问你
  │     里程碑：/update-status 把台账 + git 汇总进三文档（按 需求: REQ-00x 回写需求状态）
  ▼
[5] /seo-check：本地 check:seo + 工作站 ai-seo-studio 深度审计
  │
  ▼
[6] /deploy：本地镜像验证 → Reeve 只读探测 → 配部署目标 → dry-run → 你确认 → 部署     🔴 不可逆
  │
  ▼
[7] 上线后：Bing / 百度站长提交 sitemap；/sync-data 定期更新数据；/exp 沉淀经验
```

## 各环节产物

| 环节 | 产物 | 位置 |
|------|------|------|
| 需求 | 需求文档（目标、栏目、内容类型、数据源、SEO 目标、验收标准、里程碑） | `docs/需求文档.md` |
| 原型 | HTML + Tailwind 原型、设计令牌、组件映射 | `docs/prototypes/<页面>/` |
| 孵化 | 新项目目录、`.framework-sync.json`、`.claude/PROJECT.md`、首次提交 | 你指定的目录 |
| 台账 | 细颗粒任务（`- [ ] T12 标题` + 需求 / 读写 / 里程碑 / 文件 / 验证 / 提交） | `docs/tasks/active/*.md` |
| 阻塞 | 可逆决定与待你拍板的事 | `docs/BLOCKERS.md` |
| 进度 | 项目状态 / 待办 / 需求三文档（由 `/update-status` 汇总；只数 feat / fix 提交） | `docs/` |
| 经验 | 踩坑与禁令摘要 | `.claude/docs/experience/YYYY-MM/` |

台账格式、提交类型与进度口径、BLOCKERS 格式统一见 `CLAUDE.md`「🔴 协作约定」。

## 两道人工门为什么不能省

前两段决定「做什么」和「长什么样」，一旦进入自主循环，AI 会按台账一路做下去。
需求或原型偏了，循环跑得越顺，返工越多，所以这两处必须由你亲自点头，不交给多会话自动跑。
