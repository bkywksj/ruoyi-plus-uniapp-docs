# /dev-loop - 自主循环开发（next-ai-astro，一轮一最小提交 · 编排既有技能）

配合内置 `/loop`：`/loop /dev-loop` 自主连续开发，直到任务台账做完。本命令是「一轮的标准作业」，由 `/loop` 自动续期——干净复用原生循环，不自造。

🔴 **核心原则：本命令是「编排器」，不重复造轮子。** 新内容类型走 `/collection`、页面 / 功能走 `/dev` 的步骤、原型转码走 `html-to-code`、数据源走 `data-sync`、截图验收复用 `e2e-test`、进度汇总用 `/update-status`。
台账格式、提交类型、进度口径、阻塞记录一律以 `CLAUDE.md`「🔴 协作约定」为准。

## 用法

- `/loop /dev-loop` —— 自主连续：每轮一个最小可提交单元，自动续期，直到台账全勾完才停。
- `/dev-loop` —— 只手动跑一轮（调试 / 单步推进用）。
- 在【智码 AICoder】里且台账较大 → 优先 `/dev-orchestrate`：总控按批派子会话跑本命令（一批几条相邻任务）+ 异构验收（见下方「被编排调用时」）。

## 参数（可选 · 圈定范围）

不带参数 = 全量按台账顺序。带一个范围参数只做一部分：
- `/dev-loop T12` —— 单步：只做编号为 T12 的那一条（不带 `/loop`）
- `/dev-loop T12-T15` —— 一批：按编号顺序做 T12 到 T15（编排派活用，不带 `/loop`；区间内已勾的跳过）
- `/loop /dev-loop M2` —— 只做字段 `里程碑: M2` 的任务
- `/loop /dev-loop videos` —— 只做标题或 `文件:` 字段里含 `videos` 的任务

规则：有参数 → 每轮只在台账里筛选匹配该范围的未勾任务；做完即停。无参数 → 全量。`/loop` 续期会带着参数，范围每轮都在。

## 任务台账怎么读（与 `/dev-orchestrate`、`/progress`、`/update-status`、`/next` 同一口径）

- 台账 = `docs/tasks/active/*.md`；**只有「## 🎯 实现步骤」区块里以 `- [ ] T<数字>` / `- [x] T<数字>` 开头的行才是任务**，待决策事项、验收清单等其他复选框一律不算。
- 每条任务下的缩进字段：`需求: REQ-00x`、`读写: 写入|只读`、`里程碑: M1`（可选）、`文件:`、`验证:`、`提交:`（只读任务写 `无`）、`依赖: T11`（可选）。
- 「下一个任务」= 按编号顺序第一个未勾、且 `依赖:` 里的任务都已 `[x]` 的 `T<数字>` 行。

## 被编排调用时（参数含 `[ORCH:<总控会话id>]`）

由 `/dev-orchestrate` 在智码里派出的实现子会话，参数形如 `T12 [ORCH:xxxx]` 或 `T12-T15 [ORCH:xxxx]`。识别到该标记时：
- 标记本身不是范围参数，剥掉后按编号匹配任务；**只做参数列出的这一批（单条或区间），做完即停，不续期、不接着做批外的任务**。
- **一批按编号顺序逐条做**：每条各自走完下面的流程、**各自提交**（一条一个提交，总控和验收方按提交定位到任务）。批里某条卡住（验证门修不绿 / 需决策）→ 这条按下文报 `failed` / `blocked`，**接着做批里不依赖它的下一条**，不整批停下。
  （为什么按批：一条一个子会话时，每条都要付一次冷启动 + 重读真相源，小任务上这部分比干活还长；2026-10-29 按批派 35 条任务 3 小时 50 分钟做完，子会话之间几乎无空档。）
- 工作区里若有与本任务相关的未提交改动，视为同一编排上游产出（己方），不按 L2「疑似其他会话占用」打断用户；与本任务无关的未提交文件仍按 L1 当他者占用区，不碰。
- 流程照常走完：验证门 → 两段 review 的第二段 `/check`（第一段功能审由总控另派的验收方做，不必自调 Codex）→ 勾台账 → 按台账 `提交:` 字段提交（总控靠新提交判断完成）。验证门修不绿就不提交，如实报告。
- **只读任务**（`读写: 只读`）：结论写进任务卡（如「技术调研」区），台账勾 `[x]`，只有台账改动时提交 `docs(tasks): T12 …`；收尾行报 `status=done`。
- **遇到需决策的事**（不可逆 / 合规 / 缺凭据 / 架构级）：子会话没法问人——在 `docs/BLOCKERS.md` 追加一行 `- [ ] [需决策] YYYY-MM-DD T12 内容 → 需要谁决定什么`，不勾台账、不硬做，收尾行报 `status=blocked`。
- 需要 dev server 时用 `mcp__aicoder__resolve_and_start_task(project_path=<项目根>, command="pnpm dev", port_hint=4321)` 起（智码托管、跨子会话存活；显式传 `command`，否则可能返回「需要人工选择」卡住）。起之前先按下文「截图闭环」查端口，已有就复用。
- **界面保真截图闭环一批做一次**：批里每条照常过验证门和 `/check` 再提交；「🎨 界面保真截图闭环」放到整批做完后，对本批涉及的页面统一截图比对一次，有差异就修、追加 `fix(scope)` 提交。不必每条都开桌面 / 手机 / 深色三套截图。
- 结尾必须输出收尾小结，**批里每条一行**（包括卡住的），供总控 grep：
  `ORCH-RESULT task=<编号> status=<done|failed|blocked> commit=<短sha或none> note=<一句话：改了什么 / 卡在哪>`

## 真相源（每轮开工必读，不可凭记忆）

1. `CLAUDE.md`、`.claude/PROJECT.md`（孵化项目有才读，**优先级高于 CLAUDE.md**）、`.claude/framework-config.json`（框架核心 vs 业务代码边界）
2. **`docs/需求文档.md`** —— 需求（只读输入，本命令不改）
3. **原型** —— `docs/prototypes/*`（`/kickoff` 经工作站出的原型）
4. **任务台账** —— `docs/tasks/active/*.md`（格式见上）

## 前置门（缺则不进循环）

- **需求 / 台账都找不到** → 不瞎编，停下提示：「先走 `/kickoff` 或准备好需求 + 任务清单，再 `/loop /dev-loop`」。
- **有需求但无台账**（`docs/tasks/active/` 下没有含 `T<数字>` 任务行的文件）→ 第 0 轮自举：**激活 `writing-plans`** 读 `docs/需求文档.md` + 原型，拆**细颗粒可执行计划**写入 `docs/tasks/active/`：
  - 任务编号全局唯一：先 `grep -rhoE "^- \[[ x]\] T[0-9]+" docs/tasks 2>/dev/null` 找已有最大编号，从下一个开始
  - 任务行放在「## 🎯 实现步骤」区块，形如 `- [ ] T12 分类落地页支持分页`，字段按上文写全（每条都要有 `需求:` 和 `读写:`）
  - 内容类型类任务写明走 `/collection`，页面类写明参考文件，UI 类写明对应原型路径
  - 提交 `docs(tasks): 拆分任务台账`，然后**结束本轮**。

## 每轮标准流程（台账已存在时）

1. 读真相源，按上文规则选**一个**任务（有范围参数先过滤）。**严禁一轮做多个。**（被编排按批派时例外：一批内逐条走本流程，见上文「被编排调用时」。）
2. **判断类型 → 复用对应能力（不手搓）**：
   - **新内容类型**（新集合 + 列表 / 详情 / 分类页）→ **按 `/collection` 执行**，跳过它的方案确认步（台账即已确认的方案）。
   - **页面 / 功能** → **按 `/dev` 的步骤执行**，同样跳过其第四步确认。
   - **原型稿转页面** → **走 `html-to-code`**（HTML 原型 → `.astro` 组件 + 框架封装组件 + 语义令牌）。
   - **数据源 / 数据同步** → 激活 `data-sync`，写 `scripts/sync/sources/<名>.mjs`，`pnpm sync <名> --dry-run` 核对后再写入。
   - **SEO / GEO** → 激活 `seo-meta` / `geo-optimization`。
   - **样式 / 组件 / 动效** → 照 `ui-components` / `design-system` / `motion-transitions`。
   - **只读任务**（调研 / 审计 / 出方案）→ 结论写进任务卡，不改业务文件。
   - 用到框架里还没出现过的 Astro API 时查 `context7`（`/withastro/docs`），并对照 `CLAUDE.md`「Astro 7 版本红线」。
3. **验证门（必须全绿才提交）**：
   - `pnpm build`（= `astro check && astro build`）
   - `pnpm check:seo`（构建后 SEO / GEO 静默错误扫描）
   - `pnpm test`（改了 `src/lib` 必须补 / 改单测）
   - **UI 任务额外过「🎨 界面保真截图闭环」（见下），不达标 = 未完成。**
   - 红了当场修绿。**验证门全绿后，过下方「两段 review」才可提交。**
   - 🔴 同一目录同一时间只跑一个 `astro build` / `astro sync`（并行会搅乱内容缓存，动态路由页面整批丢失）。
4. **更新台账**：该任务 `[ ]`→`[x]`，补一行「实际改了什么 / 坑」，更新「当前进度」「下一步」。🔴 **不动 `docs/项目状态.md` / `docs/待办清单.md` / `docs/需求文档.md` 三文档**（它们由 `/update-status` 按台账的 `需求:` 字段与 git 汇总）。
5. 🔴 **两段 review 通过后，最小提交**：逐个 `git add` 本轮改动的**具体文件**（含台账文件；禁止 `git add -A`），commit 按台账 `提交:` 字段：
   - 功能 / 修复：`feat(scope): …` / `fix(scope): …`（计入业务进度）
   - 孵化项目里改了框架核心文件：那部分单独一个提交，scope 写 `framework`（如 `feat(framework): seo.ts 新增 eventJsonLd`，不计进度）；框架仓库本身正常提交
   - 只读任务 / 只改了台账：`docs(tasks): …`
   - 其余类型与计入口径见 `CLAUDE.md`「提交与进度口径」——`/progress`、`/update-status` 只数 feat / fix（scope 为 framework / strip / data / deps 除外），写错类型进度就统计不到。
6. 输出本轮小结：✅完成 T<编号> | 📊进度 X/总（只数 `T<数字>` 任务行）| ⏭️下一个。
- **里程碑边界 / 完成一个模块 / 循环收尾**：调一次 **`/update-status`** 把台账 + git 汇总进三文档；大改后跑 `/check` 规范回归。

## 子代理执行 + 两段 review（提交前必过）

主循环负责「调度 + review + 提交」，把「实现」下放。

### 子代理执行（复杂任务可选）
- 复杂 / 易上下文漂移的任务，用 **Agent 工具派一个新鲜子代理**执行单条台账任务。
- 派单时把该任务的**文件清单 + 框架约束**一并交给子代理：`BaseLayout` / `SEOHead` 统一输出 SEO、语义令牌、island 最小化、页面只调 `src/lib/*`、站内链接带结尾斜杠、`serializeJsonLd`、Astro 7 写法、首行注释、UTF-8 无 BOM、框架核心改动的提交规则。
- 轻量任务主循环直跑即可。

### 两段 review（每个任务 · 验证门绿后、提交前 · 必过）
1. **第一段 · 功能正确性**：是否真正达成任务目标；边界（空集合 / 单条 / 超长标题 / 无封面 / 无数据源凭据）、空态、有无引入回归（首页、列表、llms.txt、sitemap）。复杂逻辑可调 `code-reviewer` 子代理，或 `collaborating-with-codex`（用户点名 Codex 时）取独立第二意见。
2. **第二段 · 框架规范**：跑 **`/check <本轮改动的目录或文件>`**，审 Astro 7 写法、`BaseLayout` / `Container` / `Section` / `Button` 封装、语义令牌与 `text-brand-ink`、island 边界、`src/lib` 查询封装、结尾斜杠、JSON-LD 序列化、首行注释、UTF-8 无 BOM、框架核心改动是否单独提交。
- 🔴 **任一段不过 → 返工，不提交**；两段都过才进上方第 5 步「最小提交」。

## 🎨 界面保真截图闭环（涉及 UI 的任务必过 · 复用 e2e-test）

- **先查端口再起服务**：`netstat -ano | findstr :4321`。已有本会话（或智码任务）起的 dev server → 直接复用；没有才起 `pnpm dev`（`run_in_background`；在智码里优先 `resolve_and_start_task(command="pnpm dev")`）。**不要每轮新起一个**，也**不 kill 别人的进程**；被占用而顺延时以启动输出里的实际端口为准。地址一律写 `localhost`（本机 127.0.0.1 连不上）。
- **复用 `e2e-test` 的智码浏览器能力**：
  ```
  mcp__aicoder__browser_open(url="http://localhost:4321/<路由>/", device="desktop")   # 返回 label
  mcp__aicoder__browser_screenshot(label=<label>, full_page=true)                     # 现状（桌面）
  mcp__aicoder__browser_set_device(label=<label>, device="mobile")  → 再截一次        # 现状（手机）
  点页头主题按钮切深色 → 再截一次                                                     # 现状（深色）
  ```
- 打开对应原型当「目标」：`browser_open(url="file:///E:/<项目路径>/docs/prototypes/<页面>/index.html", device="desktop")`（也可直接传本地绝对路径），逐条比对：① 布局 / 分区 ② 主 / 辅 / 状态色 ③ 间距留白 ④ 字号字重行高 ⑤ 组件类型（`Button` / `Badge` / `Section` / 卡片 / island 用对）⑥ 文案 ⑦ 交互态（hover / focus / 空态 / 深色）。**任一不符 = 未完成，返工到达标再提交。**
- 有差异只改视图层 → 重新截图确认消除；关键差异没消除就继续修、别急着提交。
- 🔁 **失败降级（本会话级）**：第一次调浏览器就失败 → 本会话后续不反复重试，改「对照原型源码 + 用户提供截图」核对，仍逐条过 7 项。

## 决策分流 / 卡点熔断 / 停止条件

- **决策分流**（记录格式见 `CLAUDE.md`「阻塞记录」）：
  - 可逆 / 低风险 → 按合理默认继续，`docs/BLOCKERS.md` 追加 `- [ ] [可逆] YYYY-MM-DD T12 内容 → 采用的默认做法`，不空等。
  - 需决策（不可逆 / 合规 / 改动影响已上线 URL 会造成死链 / 缺外部凭据如数据源接口 key）→ 追加 `- [ ] [需决策] …` 一行后停下问用户（编排子会话按上文报 `status=blocked`）。
- **卡点熔断**：连续 3 轮无进展，或同一任务 2 轮验证门修不绿 → 停止，报错误原文 + 判断 + 建议。
- **停止条件**：范围内所有 `T<数字>` 任务行都已 `[x]` + 验证门全绿 → **先跑一次 `/update-status` 汇总三文档** → 输出「✅ 全部计划功能已实现」+ 验收自检（含一次 `/seo-check --local`），停止循环（不再续期）。

## 红线（绝不触碰）

- 🔴 **框架核心文件**（`.claude/framework-config.json` 的 `framework.core.paths`）：孵化项目里尽量不改，确需改就单独提交、scope 写 `framework`；框架仓库本身正常开发。
- **复用既有能力**（`/collection`、`/dev`、`html-to-code`、`data-sync`、`e2e-test`），别重造。
- 🔴 **规范 commit message**（类型与 scope 按「协作约定」），否则进度统计抓不到。
- 不 `git add -A`；**不碰用户未提交的改动**；不 `git reset --hard` / `clean` / `stash`；本地提交不推远端（除非明确要求，推送走 Sigil）；仓库私有。
- 反捏造：不臆造数据、播放量、案例、客户名；示例数据标明「示例」；不确定标「待确认」。
- 严守 `.claude/PROJECT.md` / `CLAUDE.md` 项目禁令（**PROJECT.md 优先级最高**）。
