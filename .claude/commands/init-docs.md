# /init-docs - 初始化项目文档

作为项目文档初始化助手，在 `docs/` 下建立三份项目文档与任务台账目录。模板在 `.claude/templates/`。

支持这些调用方式：
- `/init-docs` —— 交互式选择模式
- `/init-docs 做一个 B 站视频归类站，按系列和标签整理投稿` —— 基于描述初始化（模式三）
- `/init-docs docs/brainstorm-视频站.md` —— 基于已有需求 / 头脑风暴文档初始化（模式三）
- `/init-docs --req-only <描述或文档路径>` —— **只生成 `docs/需求文档.md`**：不建项目状态 / 待办、不建目录、**不提交**。`/kickoff` 在框架模板里用这个（需求由 `project-init` 带进新项目，框架仓库保持干净）

---

## 第零步：参数检测

| 参数类型 | 判断条件 | 处理 |
|---------|---------|------|
| `--req-only` | 参数里带这个标记 | 剥掉后按下面两行识别描述 / 路径，走模式三但**只写需求文档、不提交** |
| 无参数 | `/init-docs` 后无内容 | → 第一步（交互选择） |
| 文件路径 | 以 `.md` 结尾，或含 `/` `\` | 文件存在 → 读取后进模式三；不存在 → 提示并给出替代方式 |
| 文本描述 | 其他 | → 模式三 |

**所在仓库检查**：在框架仓库本身（`package.json` name 为 `next-ai-astro` 且没有 `.framework-sync.json`）运行、又没带 `--req-only` → 先提醒：「项目文档属于孵化出的项目，框架里只建议 `--req-only` 且不提交；确定要在框架里建全套吗？」用户坚持才继续。

## 第一步：选择模式（仅无参数时）

**上下文检测**：当前对话里已经做过头脑风暴（出现过「方案设计」「推荐方案」「实施步骤」，或激活过 `brainstorm`）→ 直接建议模式三，确认后从对话中提取结论。

否则展示：

```
请选择文档初始化模式：

1️⃣ 空白模板模式（新项目，自己填需求）
2️⃣ 扫描现有代码模式（已有页面和内容，自动生成现状报告）
3️⃣ 基于描述 / 文档初始化（推荐头脑风暴后使用，自动预填需求与待办）
```

**已存在的文档不覆盖**：`docs/` 下已有同名文档时，询问「跳过 / 合并追加 / 覆盖（需二次确认）」。

## 模式一：空白模板

1. 读取三份模板：`.claude/templates/需求文档模板.md`、`项目状态模板.md`、`待办清单模板.md`
2. 只替换可确定的占位符：项目名（取 `src/site.config.ts` 的 `name`）、当前时间（`date '+%Y-%m-%d %H:%M'`）、技术栈版本（取 `package.json`）
3. 其余占位符保留给用户填写，删掉模板里的「填充指南」注释块
4. 创建目录：

```bash
mkdir -p docs/tasks/active docs/tasks/archive docs/prototypes
```

## 模式二：扫描现有代码

> 🔴 只扫描业务代码，不把框架核心与示例算作「已完成功能」。边界以 `.claude/framework-config.json` 为准：`framework.core.paths`（框架核心）、`framework.examples.paths`（示例）、`business.paths`（业务）。

### 2.1 扫描内容

| 对象 | 方式 | 产出 |
|------|------|------|
| 路由 | `src/pages/**/*.astro`、`src/pages/**/*.ts` | 页面清单（URL / 类型：列表 · 详情 · 分类 · 文章 · 端点） |
| 内容集合 | `src/content.config.ts` 的 `defineCollection` | 集合清单、字段、loader 类型 |
| 数据规模 | `src/data/*.json` 数组长度、`src/content/**/*.md` 文件数 | 各集合条目数；示例数据是否已替换 |
| 数据源 | `scripts/sync/sources/*.mjs` | 数据源名、输出文件、是否启用、所需环境变量名 |
| island | `grep -rn "client:" src --include=*.astro` | 交互组件清单 |
| 站点配置 | `src/site.config.ts` | 站名、域名是否仍为占位、导航 |
| 代码待办 | `TODO` / `FIXME` / `XXX`（`src`、`scripts`） | 待办候选（带文件:行） |
| 站点健康 | 有 `dist/` 时 `pnpm check:seo` | SEO 错误 / 警告数 |

### 2.2 Git 提交分析

```bash
git log -50 --format="%h|%ad|%s" --date=short --no-merges
```

按 `CLAUDE.md`「提交与进度口径」只取业务进度提交（`feat` / `fix`，scope 不是 `framework` / `strip` / `data` / `deps`），过滤同步提交后，按 scope 归并出「已完成的功能」与完成日期。

### 2.3 生成文档

- **项目状态.md**：页面与内容概览表、已完成（来自提交）、进行中（有活跃任务时）、待办（来自 TODO）、站点健康、问题与风险（占位域名、示例数据未替换、check:seo 错误）
- **需求文档.md**：把已实现的页面 / 集合反推为 REQ（状态「已完成」），技术栈从 `package.json` 读；无法从代码推断的业务目标标「待补充」
- **待办清单.md**：FIXME → 高，TODO → 中，优化类 → 低；附来源文件与行号

**质量要求**：数字全部来自实际扫描；推断的内容明确标注「推断」；不编造业务目标。

## 模式三：基于描述 / 文档

### 输入来源（优先级）

1. 当前对话中的头脑风暴结论
2. 参数指定的文档
3. 参数里的文本描述

### 提取信息

| 信息 | 用途 |
|------|------|
| 站点名称与一句话定位（「X 是 Y」） | 项目概述、site.config 的 tagline 建议 |
| 目标受众 | 需求概述 |
| 栏目与 URL | 信息架构表 |
| 内容类型（集合）与字段 | 内容类型需求（每类一个 REQ） |
| 数据源与凭据需求 | 数据源章节（只记变量名，不记值） |
| SEO / GEO 目标 | SEO 章节 |
| 设计方向 | 设计要求 |
| 实施步骤 / 路线图 | 待办与项目状态的实施进度 |
| 风险 | 问题与风险 |

提取后先展示摘要请用户确认，再生成：

- **需求文档.md**：按模板完整填写；每条需求一个全局唯一 `REQ-00x`（任务台账用 `需求: REQ-00x` 引用它）；路线图写进「里程碑」表（M1 / M2…各含哪些 REQ）；不确定的写「待确认」
- **项目状态.md**：阶段「规划中」，实施进度表（全部 ⏳ 待开始）——`--req-only` 时不生成
- **待办清单.md**：实施步骤前 1-2 步 → 高优先级，中间 → 中，测试 / 优化 / 上线准备 → 低——`--req-only` 时不生成

> 这里不直接写任务台账：台账由 `writing-plans`（或 `/dev-loop` 第 0 轮）按需求 + 原型拆成 `T<编号>` 任务，格式见 `CLAUDE.md`「协作约定」。

## 输出确认

```markdown
✅ 项目文档初始化完成（模式 {一 / 二 / 三}）

📁 已创建：
- docs/需求文档.md
- docs/项目状态.md
- docs/待办清单.md
- docs/tasks/active/、docs/tasks/archive/、docs/prototypes/

📊 概要：{REQ X 个 / 待办 Y 项 / 页面 Z 个 / 集合 N 个}

💡 下一步：
1. 检查并调整生成的文档
2. 需要原型 → /kickoff 阶段二（工作站出原型）
3. 需求与原型就绪 → 拆任务台账（writing-plans，任务编号 T1、T2…全局唯一）→ /loop /dev-loop
```

提交（`--req-only` 不提交）：逐个 `git add` 新建的文档 → `git commit -m "docs(tasks): 初始化项目文档"`。

---

## 注意事项

- 时间一律 `YYYY-MM-DD HH:MM`，东八区（系统时区，直接用裸 `date`）
- 不覆盖用户已有文档；合并时保留用户内容
- 反捏造：业务目标、受众、数据量等事实只来自用户描述或代码；拿不准写「待确认」
- 文件 UTF-8 无 BOM

## 与其他命令的关系

| 命令 | 关系 |
|------|------|
| `/kickoff` | 阶段一产出需求文档时调 `/init-docs --req-only`（只出需求、不提交） |
| `/update-status` | 初始化之后由它持续维护三文档 |
| `/add-todo` | 补充单条待办 |
| `brainstorm` 技能 | 头脑风暴后用模式三直接落文档 |
