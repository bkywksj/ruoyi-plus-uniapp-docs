# /add-todo - 快速添加待办事项

作为待办管理助手，把一句话待办解析后加入 `docs/待办清单.md`，并联动 `docs/项目状态.md`。

## 使用方式

```
/add-todo 视频详情页加上一集 / 下一集导航
/add-todo 修复分类页描述重复，优先级高
/add-todo 首页加热门视频区块，2天，中等优先级
/add-todo videos 数据源增加合集字段
/add-todo SEO 给文章页补 dateModified
```

---

## 第一步：检测文档

`docs/待办清单.md` 不存在 → 读 `.claude/templates/待办清单模板.md`，替换时间占位符后创建，提示 `📝 已自动创建 docs/待办清单.md`。

## 第二步：解析任务信息

| 信息 | 解析方式 | 默认值 |
|------|---------|--------|
| 任务名称 | 主体内容，动词开头，≤ 15 字 | 必填 |
| 优先级 | 高 / 中 / 低，或 紧急 / 重要 | 中 |
| 预计工作量 | 「X 天」「X 周」 | 待定 |
| 所属模块 | 见下表 | 通用 |
| 截止日期 | 「截止 XX」「deadline XX」 | 待定 |
| 关联需求 / 任务 | 输入里出现 `REQ-003`、`T12` | 无（有才写；`/update-status` 靠它精确匹配完成状态） |

### 优先级映射

| 用户输入 | 映射到 |
|---------|--------|
| 高、紧急、urgent、critical、ASAP | 🔥 高优先级 |
| 中、一般、normal、默认 | 📌 中优先级 |
| 低、可延后、optional、nice-to-have | 💡 低优先级 |

### 模块识别

| 用户输入前缀 / 关键词 | 所属模块 |
|---------------------|---------|
| 集合名（`videos`、`works`、`posts`…） | 集合：{名} |
| 路由（`/videos/`、「详情页」「列表页」「分类页」「首页」） | 页面：{路由} |
| 「数据源」「同步」「接口」 | 数据源：{名} |
| 「SEO」「GEO」「llms」「结构化数据」「sitemap」 | SEO / GEO |
| 「样式」「配色」「深色」「动效」 | 设计 |
| 「部署」「上线」「域名」「备案」 | 部署 |
| 无前缀 | 通用 |

## 第三步：写入 待办清单.md

按优先级追加到对应区域：

```markdown
## 🔥 高优先级（紧急重要）
- [ ] {任务名称}
  - 截止日期: YYYY-MM-DD（有才写）
  - 描述: {一句话}（有才写）
  - 所属模块: {模块}
  - 关联需求: REQ-003 / T12（有才写）
  - 预计工作量: X 天（有才写）
  - 添加时间: YYYY-MM-DD HH:MM
```

> 待办清单只是「想到的事」的收集箱，不是任务台账：`/dev-loop` 不会从这里取任务。要让自主循环去做，得拆成台账里的 `T<编号>` 任务（见下方「智能提示」）。

更新「待办总数」「最后更新」。时间用 `date '+%Y-%m-%d %H:%M'`。

## 第四步：联动 项目状态.md（存在时）

在「📋 待办」区域追加同一条（格式与待办清单一致，含优先级、工作量、所属模块）。

## 第五步：输出确认

```markdown
✅ 已添加待办：

📌 **{任务名称}**
- 优先级: {高 / 中 / 低}
- 所属模块: {模块}
- 预计工作量: {X 天 / 待定}

📁 已更新: docs/待办清单.md{、docs/项目状态.md}
📊 当前待办总数: X 项
```

---

## 批量添加

分号、换行、数字编号都可以分隔多条：

```
/add-todo 视频列表加排序；系列页；首页热门区块
```

依次解析、批量写入、汇总报告。

## 智能提示

| 情况 | 提示 |
|------|------|
| 待办 > 15 项 | 建议运行 `/progress` 梳理优先级，低优先级考虑归档 |
| 高优先级 > 5 项 | 建议重新评估，确保「紧急」真正紧急 |
| 与已有待办相似 | 列出已有条目，询问是否同一任务 |
| 任务复杂（描述 > 20 字、含「设计 / 重构 / 对接 / 迁移」、多个动词、跨多个页面或集合） | 建议拆进任务台账：说「拆解任务」（`writing-plans`，按 `CLAUDE.md`「协作约定」写 `- [ ] T<编号>` 任务行，编号接着台账里已有的最大编号），或直接 `/dev` / `/collection` |
| 想交给自主循环做 | 同上，拆成台账任务后 `/loop /dev-loop`；待办清单本身不会被循环消费 |

## 与其他命令的关系

| 命令 | 关系 |
|------|------|
| `/update-status` | 批量同步；/add-todo 单条添加 |
| `/init-docs` | 初始化文档；/add-todo 可自动补建待办清单 |
| `/progress` `/next` | 读取待办进行统计与推荐 |
| `writing-plans` / `task-tracker` | 复杂任务拆成台账 `T<编号>` 任务，跟踪步骤、方案与进度 |
