# /update-status - 智能更新项目状态

作为项目状态更新助手，把 `docs/tasks/active/` 台账与 git 提交里的真实进展，汇总进三份项目文档。

> 🔴 分工：三文档里的**进度类内容**（已完成、进行中、需求状态、统计）只由本命令汇总；`/init-docs` 负责初建，`/add-todo` 只追加单条待办；`/dev-loop` 每轮只动 `docs/tasks/active/`，里程碑时调本命令。
> 台账格式与进度口径以 `CLAUDE.md`「🔴 协作约定」为准。

---

## 第一步：检测文档状态

检查 `docs/项目状态.md`、`docs/待办清单.md`、`docs/需求文档.md`：

| 缺失的文档 | 创建方式 |
|-----------|---------|
| 项目状态.md | 读 `.claude/templates/项目状态模板.md`，按第二步的扫描结果填初始数据 |
| 待办清单.md | 读 `.claude/templates/待办清单模板.md`，代码里的 TODO / FIXME 作为初始待办 |
| 需求文档.md | 读 `.claude/templates/需求文档模板.md`，技术栈从 `package.json` 读版本；无法从代码推断的业务目标标「待补充」 |

创建后提示：`📝 已自动创建 docs/xxx.md`。时间用 `date '+%Y-%m-%d %H:%M'`（🔴 禁止 `TZ=Asia/Shanghai`、禁止硬编码 `+08:00`）。

---

## 第二步：分析最新状态

### 2.1 读取现有文档
记录项目状态.md 里「已完成 / 进行中 / 待办」各区域的条目，保留用户手写内容。

### 2.2 Git 提交（按进度口径过滤）

```bash
git log -30 --format="%H|%an|%cn|%ad|%s" --date=short --no-merges
```

口径来自 `.claude/framework-config.json` 的 `progress`（`countCommitTypes` / `excludeScopes`），与 `CLAUDE.md`「提交与进度口径」一致：

| 分类 | 识别方式 | 计入业务进度 |
|------|---------|:-----------:|
| 业务进度提交 | 类型为 `feat` / `fix`，且 scope 不是 `framework` / `strip` / `data` / `deps` | ✅ |
| 框架与维护提交 | `feat(framework)`、`refactor(strip)`、`chore(data)`、`docs(tasks)` 等其余一切 | ❌ |
| 同步提交 | message 含 `cherry picked from`，或以 `chore(framework-sync)` 开头，或 author ≠ committer | ❌（单独列出） |

只从「业务进度提交」里提取「完成了什么」与完成日期（按 scope 归并，如 `feat(videos)` 多条归为「视频内容类型」）。

### 2.3 扫描业务代码（以 `.claude/framework-config.json` 为准）

- **路由**：`src/pages/**` 下的页面与端点，区分业务 / 框架示例
- **内容集合**：`src/content.config.ts` 里的集合；各集合条目数（JSON 数组长度 / Markdown 文件数）
- **数据源**：`scripts/sync/sources/*.mjs`（启用状态）
- **代码待办**：`src`、`scripts` 里的 `TODO` / `FIXME` / `XXX`，记录文件与行号，与现有待办对比识别新增 / 已解决
- **站点健康**：有 `dist/` 时运行 `pnpm check:seo`（不重新构建；dist 可能不是最新，报告里注明构建时间），记录错误 / 警告数
- **阻塞记录**：`docs/BLOCKERS.md` 里未勾的 `[需决策]` / `[可逆]` 行数

### 2.4 读取任务台账

```bash
grep -rnE "^- \[[ x]\] T[0-9]+" docs/tasks/active/ 2>/dev/null
```

🔴 **只有「## 🎯 实现步骤」区块里以 `- [ ] T<数字>` / `- [x] T<数字>` 开头的行是任务**；待决策事项、验收清单等其他复选框不参与统计。

| 读取区域 | 提取信息 |
|---------|---------|
| 文件头部 | 台账名、状态、更新时间 |
| 任务行 + 字段 | 每条 `T<编号>` 的完成状态、`需求: REQ-xxx`、`里程碑:`、`读写:` |
| 当前进度 | 正在进行、下一步 |
| 问题记录 | 未解决问题数 |

另查 `docs/tasks/archive/` 统计本月归档数（有才统计）。

## 第三步：更新 项目状态.md

1. **已完成**：新完成的功能 / 页面 / 内容类型，日期取自提交，附提交短 hash
2. **进行中**：按台账更新进度；台账超过 7 天未更新的标 ⚠️
3. **待办**：新发现的 TODO，标注优先级与所属模块（页面 / 集合 / 数据源 / SEO）
4. **页面与内容概览**：刷新路由表与集合条目数（示例数据单独标注，不计入业务进度）
5. **活跃任务**区域（不存在则在「进行中」后新增）：

```markdown
## 活跃任务（来自 task-tracker）

| 台账 | 状态 | 任务进度 | 里程碑 | 最后更新 |
|------|------|---------|--------|---------|
| {台账名} | 🟢 进行中 | X/Y (Z%)（只数 T 任务行） | M1 3/3、M2 1/4 | YYYY-MM-DD |
```

6. **站点健康**：check:seo 结果、生产域名是否已配置
7. **问题和风险**：`docs/BLOCKERS.md` 里未处理的 `[需决策]` 项逐条列出
8. **统计**：「最后更新」（`YYYY-MM-DD HH:MM`）、「整体进度」= 已完成 REQ / 总 REQ（没有需求文档时用台账任务完成率，并注明口径）、「下一步计划」

---

## 第四步：联动更新 待办清单.md

- **同步完成**：项目状态.md 新增的已完成项，在待办清单里找到对应条目（优先按 `关联需求: REQ-xxx` / `T<编号>` 精确匹配，其次按任务名 / 模块模糊匹配）移到「最近完成」，附完成日期
- **同步新增**：新扫到的代码待办按级别入列 —— `FIXME` / `URGENT` → 高；`TODO` → 中；`OPTIMIZE` / `ENHANCE` → 低；记录来源文件与行号
- **统计**：待办总数、本周完成、完成率（最近完成 /（最近完成 + 未完成））

---

## 第五步：联动更新 需求文档.md（按 `需求:` 字段回写）

- 对每个 `REQ-xxx`，汇总台账里 `需求: REQ-xxx` 的全部任务：
  - 全部 `[x]` → 状态改为「已完成」，完成日期取最后一个相关业务进度提交的日期
  - 部分 `[x]` → 「开发中」
  - 没有任何任务引用 → 保持原状态，报告里列为「未拆任务的需求」
- 没写 `需求:` 字段的任务 → 不据此改需求状态，在报告里列出请用户补字段或确认
- `package.json` 里 Astro / Tailwind / React 等主版本有变化时，更新技术栈表

---

## 第六步：提交

```bash
git add docs/项目状态.md docs/待办清单.md docs/需求文档.md    # 只加本次改动的文档，逐个添加
git commit -m "docs(tasks): 汇总进度（{简述}）"
```

`docs` 类型不计入业务进度，这是预期的——文档汇总本身不是功能开发。

## 第七步：输出更新报告

```markdown
# 📝 项目状态更新报告

**更新时间**: {YYYY-MM-DD HH:MM}

## 文档状态
- ✅ docs/项目状态.md —— 已更新
- ✅ docs/待办清单.md —— 已同步
- ✅ docs/需求文档.md —— 已同步

## 本次变更
### 项目状态.md
- 新增已完成 X 项 / 更新进行中 X 项 / 新增待办 X 项
### 待办清单.md
- 移至已完成 X 项 / 新增 X 项 / 当前总数 X 项
### 需求文档.md
- 状态更新 X 个 REQ（已完成 X / 开发中 X）

## 主要完成内容
1. {功能 / 页面 / 内容类型}（REQ-xxx，T12 / T13）

## 发现的问题
- ⚠️ {超过 7 天未更新的台账}
- ⚠️ {BLOCKERS 里待决策项 / 未拆任务的需求 / 缺 `需求:` 字段的任务}
- ⚠️ {check:seo 错误 / 示例数据未替换 / 域名仍是占位}

## 下一步
> 运行 `/next` 获取具体的下一步开发建议
```

## 注意事项

- **保留用户手写内容**：只更新能从代码 / git / 台账分析出的信息；存疑时追加而不覆盖
- **匹配不确定**时，在报告里列出请用户确认，不强行改状态
- **数字全部来自实际统计**，不估算、不美化
- 时间格式 `YYYY-MM-DD HH:MM`，东八区（系统时区即东八区，直接用裸 `date`）

## 与其他命令的关系

| 命令 | 关系 |
|------|------|
| `/init-docs` | 初始化时创建三文档，之后由 /update-status 汇总进度 |
| `/add-todo` | 单条添加待办；/update-status 批量同步 |
| `/progress` | 只读分析；/update-status 修改文档 |
| `/dev-loop` `/dev-orchestrate` | 里程碑与收尾时调用本命令 |
| `task-tracker` / `writing-plans` | 台账的格式与生产者；本命令只读取汇总 |
