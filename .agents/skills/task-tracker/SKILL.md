# 任务跟踪技能

## 何时使用

- 多步骤功能开发（需要跨会话）
- 复杂需求的步骤分解与跟踪
- 方案讨论和技术调研记录
- 问题记录和解决过程跟踪
- 任务进度记录与更新
- 中断后的任务恢复
- 历史任务查询与归档

其他常见说法：跟踪任务、恢复任务、任务列表、归档任务、方案讨论、记录方案、技术调研、遇到问题。

✅ 用户明确要求跟踪任务（"创建任务跟踪"、"记录进度"、"跟踪这个任务"）
✅ 复杂的多步骤开发任务、需要跨会话恢复的工作
❌ 简单的单步操作、纯咨询性对话

> 台账格式以 `CLAUDE.md`「🔴 协作约定」为准，`writing-plans`、`/dev-loop`、`/dev-orchestrate`、`/progress`、`/update-status`、`/next` 读的都是同一格式。本技能负责台账的**容器与日常维护**，成体系的细颗粒计划由 `writing-plans` 生产。

## 台账三条硬规则

1. **任务编号全局唯一**：`T1`、`T2`…跨台账文件递增（含已归档的），写在任务行里：`- [ ] T12 分类落地页支持分页`。
2. **只有「## 🎯 实现步骤」区块里以 `- [ ] T<数字>` / `- [x] T<数字>` 开头的行才是任务**。待决策事项、验收清单等其他区块的复选框不参与「下一个任务」「全部完成」的判断，也不算进度。
3. **每条任务下写缩进字段**：`需求: REQ-003`、`读写: 写入|只读`、`里程碑: M1`（可选）、`文件:`、`验证:`、`提交:`（只读任务写 `无`）、`依赖: T11`（可选）。

## 🔴 多会话下怎么选台账文件

用户可能同时开多个会话，`docs/tasks/active/` 里「最新修改的文件」不一定是你的。**不要默认 `ls -t | head -1` 取最新的去改。** 按下面顺序确定 `TASK_FILE`：

1. 本会话创建或已经在读的台账 → 直接用它
2. 用户点名了任务编号 → `grep -l "^- \[[ x]\] T12 " docs/tasks/active/*.md`
3. 用户给了关键词 → `ls docs/tasks/active/ | grep 关键词`
4. 仍不确定、且活跃台账不止一个 → 列出清单（标题 / 进度 / 最后更新）请用户选，**不要猜**

只改本会话负责的台账；不删除、不归档别人的台账（CLAUDE.md「跨会话操作禁令」）。

## 核心操作

> Bash 工具每次调用都不保留变量：下面每段命令都要在**同一次调用里**先给 `TASK_FILE` / `TASK_ID` 赋值再用。时间一律裸 `date`（东八区），禁止 `TZ=Asia/Shanghai`。

### 1. 创建任务

**触发**：用户说"创建任务跟踪"、"记录这个任务"

```bash
mkdir -p docs/tasks/active docs/tasks/archive
# 已有最大任务编号（含归档）；无输出 = 从 T1 开始
grep -rhoE "^- \[[ x]\] T[0-9]+" docs/tasks 2>/dev/null | grep -oE "[0-9]+$" | sort -n | tail -1
# 文件名：task-{YYYYMMDD-HHMMSS}-{任务简称}.md
date +%Y%m%d-%H%M%S
```

然后用 Write 工具按上方模板写 `docs/tasks/active/task-<时间>-<简称>.md`，任务从「最大编号 + 1」开始编。
首次使用时顺带创建 `docs/tasks/README.md`（内容见下）。创建后提交：`git add <台账文件> docs/tasks/README.md` → `git commit -m "docs(tasks): 新建任务台账 <简称>"`。

**README.md 内容**（外层用 `~~~` 围栏，内层代码块才不会把它截断）：

~~~markdown
# 任务跟踪中心

## 目录说明
- `active/` - 进行中的任务
- `archive/` - 已完成的任务（按月归档）

## 台账格式
- 任务写在「## 🎯 实现步骤」区块：`- [ ] T12 标题`，编号全局唯一
- 字段：需求 / 读写 / 里程碑 / 文件 / 验证 / 提交 / 依赖

## 快速恢复
```bash
ls -1 docs/tasks/active/                                  # 查看活跃任务
grep -l "^- \[[ x]\] T12 " docs/tasks/active/*.md          # 按编号找台账
```
~~~

### 2. 更新进度

**触发**：用户说"更新进度"、"标记 T12 完成"

```bash
TASK_ID="T12"
TASK_FILE=$(grep -l "^- \[[ x]\] ${TASK_ID} " docs/tasks/active/*.md)
[ -n "$TASK_FILE" ] || { echo "找不到 ${TASK_ID}"; exit 1; }

# 勾选（编号后带空格，避免 T12 误伤 T120）
sed -i "s/^- \[ \] ${TASK_ID} /- [x] ${TASK_ID} /" "$TASK_FILE"

# 更新时间戳
NOW=$(date '+%Y-%m-%d %H:%M:%S')
sed -i "s/^\*\*更新时间\*\*:.*/**更新时间**: ${NOW}/" "$TASK_FILE"

# 进度：只数「实现步骤」区块里的 T 任务行
awk '/^## /{steps = ($0 ~ /实现步骤/)} steps && /^- \[[ x]\] T[0-9]+ /{total++; if ($0 ~ /^- \[x\]/) done++} END{printf "%d/%d (%d%%)\n", done, total, total ? done * 100 / total : 0}' "$TASK_FILE"
```

之后用 Edit 工具：在该任务下补 `完成时间:` / `实际结果:`，更新「当前进度」的数字与「下一步操作」，在文末「变更记录」追加一条。提交 `docs(tasks): T12 完成 <一句话>`（代码改动由任务自己的 `提交:` 字段那次提交负责，台账可随同一次提交）。

### 3. 列出活跃任务

**触发**：用户说"有哪些任务"、"列出任务"

```bash
for file in docs/tasks/active/*.md; do
  [ -e "$file" ] || continue
  TITLE=$(grep -m1 "^# 任务：" "$file" | sed 's/^# 任务：//')
  STATUS=$(grep -m1 "^\*\*状态\*\*:" "$file" | sed 's/.*: //')
  UPDATED=$(grep -m1 "^\*\*更新时间\*\*:" "$file" | sed 's/.*: //')
  PROGRESS=$(awk '/^## /{steps = ($0 ~ /实现步骤/)} steps && /^- \[[ x]\] T[0-9]+ /{total++; if ($0 ~ /^- \[x\]/) done++} END{printf "%d/%d", done, total}' "$file")
  echo "📄 $TITLE ｜ 状态: $STATUS ｜ 进度: $PROGRESS ｜ 更新: $UPDATED"
  echo "   $file"
done
```

### 4. 恢复任务

**触发**：用户说"继续上次的任务"、"恢复任务"

1. 按「多会话下怎么选台账文件」确定 `TASK_FILE`（活跃台账不止一个又没点名时，先列清单请用户选）
2. Read 整份台账
3. 输出恢复信息：任务标题、进度（只数 T 任务行）、选定方案与理由、下一个未勾且依赖已满足的任务、未解决的问题与 `docs/BLOCKERS.md` 里相关的未处理项
4. 用户确认后继续

### 5. 记录方案讨论

**触发**：用户说"记录方案讨论"、"添加方案"、"方案对比"

用 Edit 工具在「🎨 方案设计」下追加方案 C、D…，或更新「最终选择」；在「变更记录」追加：

```markdown
### 2026-09-26 16:45
**变更类型**: 方案调整

**变更内容**:
- 添加方案讨论：{一句话}
```

**操作指南**：逐个记录每个方案的优缺点；记录对比维度（性能、成本、复杂度等）；写清选择理由和权衡；保留备选方案。

### 6. 记录技术调研

**触发**：用户说"记录技术调研"、"添加技术选型"、"技术对比"

在「🔍 技术调研」更新选型表、调研结论、参考资料，并追加变更记录。
**操作指南**：对比至少 2-3 个方案；记录版本号；评估学习成本和风险；保存参考链接。重要选型另存 `docs/decisions/`（见 `tech-decision`）。

### 7. 记录问题

**触发**：用户说"记录问题"、"遇到问题"、"添加问题"

在「🐛 问题记录」追加：现象、影响范围、根本原因、解决方案、状态；解决后补解决时间。挡住进度又需要别人拍板的，同时按上方格式记入 `docs/BLOCKERS.md`。
**操作指南**：及时记录；分析根因而不是表面现象；解决后及时更新状态。

### 8. 归档任务

**触发**：用户说"任务完成"、"归档任务"（**由用户决定，不自动归档**）

```bash
TASK_FILE="docs/tasks/active/task-20260121-153045-视频合集页.md"
# 归档前确认实现步骤里没有未勾的 T 任务
awk '/^## /{steps = ($0 ~ /实现步骤/)} steps && /^- \[ \] T[0-9]+ /' "$TASK_FILE"

sed -i "s/^\*\*状态\*\*:.*/**状态**: 🔵 已完成/" "$TASK_FILE"
YEAR_MONTH=$(date +%Y-%m)
mkdir -p "docs/tasks/archive/$YEAR_MONTH"
git mv "$TASK_FILE" "docs/tasks/archive/$YEAR_MONTH/"
```

文件名保持不变（编号全局唯一，归档后也能被 `grep` 找到）。提交 `docs(tasks): 归档 <简称>`。

## 最佳实践

**应该做**：
- ✅ 一个台账 = 一个完整功能；台账里每条 T 任务 = 一个最小可提交单元
- ✅ 及时更新进度（完成一条勾一条）
- ✅ 详细记录关键决策、方案讨论过程和选择理由
- ✅ 保留原始需求描述，任务关联 `需求: REQ-00x`
- ✅ 及时记录遇到的问题（问题、原因、解决方案）
- ✅ 下一步操作要有上下文（依赖、预期结果）

**不应该做**：
- ❌ 为每个小改动创建台账
- ❌ 删除旧任务（归档即可）；不改、不删别的会话的台账
- ❌ 自动归档（由用户决定）
- ❌ 在「实现步骤」以外的区块写 `- [ ] T<数字>` 行，或任务行不带编号
- ❌ 复用或重排已发出的任务编号

## 错误处理

**目录不存在** → 自动创建 `docs/tasks/active` 和 `archive`

**没有活跃任务** → 提示用户：创建新任务 | 恢复归档任务 | 查看历史

**文档格式错误** → 尽量解析，提示用户保持格式：
- 保持 `##` 标题层级，任务只写在「## 🎯 实现步骤」区块
- 任务行格式：`- [ ] T12 标题` 或 `- [x] T12 标题`
- 不删除 `**字段**` 标记

## 功能边界

**适用于**：单人或多会话协作开发、本地存储、快速恢复上下文

**不适用于**：多人实时协作、复杂依赖管理（请使用专业项目管理工具）
